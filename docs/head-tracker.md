# ヘッドトラッカー

M5StickS3の加速度・ジャイロから姿勢を推定し、Wi-FiのOSC / UDP、またはUSBでWindowsアプリに送ります。
PCアプリは姿勢を表示し、頭の回転を打ち消す逆回転をIEM SceneRotatorへ送ります。
音声はこのアプリを通りません。DAW側で処理します。

## 起動と初期設定

Windowsでは、`tools/head-tracker-monitor/`内の[`start-head-tracker-monitor.cmd`](../tools/head-tracker-monitor/start-head-tracker-monitor.cmd)を
ダブルクリックするだけでGUIを起動できます。デスクトップにこのファイルのショートカットを置いても使えます。
ショートカットの作業フォルダーによらず、ランチャー自身の場所からプロジェクトを見つけます。
uvは事前にインストールしてください。初回は依存パッケージを自動で準備するため、時間がかかる場合があります。
一緒に開くコマンド画面はGUIを終了すると閉じます。失敗時はエラーを確認できるよう画面を残します。

FWの書き込みや、コマンドから起動する場合は次の手順を使います。
リポジトリのルートで実行します。`COM7`は実際のポート名に置き換えてください。

```powershell
uv run m5pio devices
uv run m5pio build head-tracker
uv run m5pio upload head-tracker --port COM7
uv run --project tools/head-tracker-monitor --frozen head-tracker-monitor
```

PCアプリはPython 3.14、PySide6、python-osc、pyserialを使用します。
専用の`uv.lock`で依存関係を固定し、FWの開発環境とは別の仮想環境にインストールします。
初回起動にはパッケージのダウンロードが必要です。exe配布と他OSでの動作保証は初期版に含めません。

### USBで使う場合

1. USBで本体を接続し、シリアルモニターを終了します。
2. PCアプリの「USBポート」でM5StickS3を選びます。
3. 「姿勢データの入力」を「USB（シリアル）」に切り替えます。
4. 本体を静止させて校正が終わると、姿勢と受信頻度が表示されます。送信元は`USB COM4`などと表示されます。

Wi-FiのSSID・パスワード・送信先PCの設定は不要です。USBからの給電と姿勢の連続受信ができます。
受信中も同じUSB接続を使って、本体の設定と状態取得を行えます。
ポートを変更した場合は「接続開始 / 再開」を押してください。

### Wi-Fiで使う場合

1. 「姿勢データの入力」を「Wi-Fi（OSC / UDP）」にして、USBで本体を接続し、シリアルモニターを終了します。
2. PCアプリの「USBポート」でM5StickS3を選びます。ESP32のUSB機器を優先して表示します。
3. 2.4GHz Wi-FiのSSIDとパスワードを入力します。PCも同じLANにつながっている必要があります。
4. 「送信先PC IPv4」に、本体から到達できるPCのLAN側アドレスを指定します。複数候補がある場合は同じLANのものを選びます。`127.0.0.1`は指定できません。
5. 受信UDPポートを確認します。初期値は9000です。
6. 「Wi-Fi設定と送信先を保存して接続」を押します。SSID、パスワード、送信先IP・ポートを本体のNVSに保存します。
7. 数秒後に「本体の設定・Wi-Fi接続状況を確認」を押すと、保存済みの設定、Wi-Fiの状態と本体IPを確認できます。
8. 校正が終わると左側に「追跡中」、受信頻度と姿勢が表示されます。

設定画面のパスワードは送信時に消去し、PCの設定ファイルやログには保存しません。
USB応答にもパスワードを含めません。本体には再接続用のパスワードが保存されます。
Wi-Fi設定は変更するまで再利用します。USBを外しても動作します。
PCのIPアドレスや受信ポートを変えた場合は、USB経由で「姿勢データの送信先を変更」を押してください。
SSIDとパスワードを再入力せず、保存済みのWi-Fi設定を維持できます。
候補にはアダプター名も表示し、物理LANを仮想アダプターより優先して並べます。

### 入力の切り替え

「姿勢データの入力」を変更すると、その入力だけを受け付けます。
切り替え後の最初の有効姿勢を正面とするため、正面を向いた状態で切り替えてください。
本体のWi-Fi設定は保持され、USB入力中も本体からのWi-Fi送信は継続します。
Wi-FiとUSBの混在による二重中継は行いません。

USB切断時は中継を止め、選択した同じポートへの再接続を待ちます。Wi-Fiへ自動では切り替えません。
USBが再接続できたら、その時点の姿勢を正面にして再開します。
有効姿勢が500ms届かない場合の中継停止と、SceneRotatorへの出力方法は両方の入力で共通です。

GUIの入力方式・USBポート・受信UDPポート・SceneRotator送信先は、終了時にWindowsのユーザー設定へ保存します。
中継は起動時にOFFになります。

3D表示の初期視点は後方です。自分と同じ方向を向く頭を見るため、左を向くとモデルも画面の左へ向き、
左耳を上げるとモデルの左側が上がります。上部の選択欄で正面からの対面表示にも切り替えられます。
正面視点では左右の見え方が逆になります。視点の切り替えは描画だけを変え、角度とOSC送信には影響しません。

## 取り付けと操作

ヘッドフォンの上で、画面を上、USB端子を後ろへ向けて固定します。
画面の回転設定は表示だけに適用し、センサーの軸変換には使いません。

| 操作 | 動作 |
| --- | --- |
| 電源投入 | 約3秒の静止校正、その後約3秒の姿勢推定の初期化 |
| Aボタン | 現在の姿勢全体を正面・水平の基準にする |
| Bボタン3秒長押し | 静止校正からやり直す。セッションも更新する |
| GUIの正面設定 | PC側で現在の姿勢全体を基準にする |

本体は縦向きの画面で、Aボタンで設定した正面を指す黄色い矢印を表示します。
画面上端の`HEAD`が本体の前方です。左を向くと矢印は右へ回り、設定した正面の方角を保ちます。
起動・再校正後は最初の追跡姿勢を基準にします。正面方向が画面に垂直になるほど傾けると、
矢印の代わりに`UP`または`DOWN`を表示します。
GUIの正面設定はPC側だけに適用されるため、本体の矢印も合わせる場合はAボタンを使ってください。
方向表示もYawと同様にジャイロのドリフトの影響を受けるので、必要に応じて正面を合わせ直します。

画面はメモリー上の画像を完成させてからまとめて転送し、約20Hzで更新します。
実画面をいったん黒く消す更新を避け、周期的なちらつきを抑えます。

校正中は机などに置いて動かさないでください。取り付けた状態でも静止できれば校正できます。
動きを検出すると3秒の計測窓をやり直すため、校正終了までの時間は延びます。
基準は最初の有効な受信姿勢で自動設定し、再校正後にも取り直します。
Wi-Fiだけが切断した場合は姿勢推定と基準を維持します。

内蔵BMI270は加速度とジャイロの6軸IMUです。磁気方位の基準がないためYawは徐々にずれます。
正面を向いてAボタン、またはGUIの正面設定で合わせ直してください。
長時間の絶対方位維持や位置移動の検出には対応しません。

## 座標と姿勢推定

右手系で、頭の前を+X、左を+Y、上を+Zとします。
Hamiltonクォータニオンを`w, x, y, z`の順に扱い、頭部座標から基準座標への回転を表します。
Yaw・Pitch・Rollは表示のためのZYXオイラー角で、単位はdegreeです。

| 正の角度 | 動き |
| --- | --- |
| Yaw（Z軸） | 左を向く |
| Pitch（Y軸） | 下を向く |
| Roll（X軸） | 左耳が上がる |

Pitchが±90度付近では表示用オイラー角が不安定になる場合があります。
推定・中継・立体描画にはクォータニオンを使います。

FWはM5Unifiedの論理軸から`頭X = −センサーX、頭Y = −センサーY、頭Z = センサーZ`へ変換します。
初期実装でPitchとRollの入れ替わりと下向きでのRollマイナスを実機で確認し、この割り当てに修正しました。
修正後の取り付け時の符号は、下記の実機チェックで確認してください。
本体の見た目だけで合否を決めず、各軸を単独で動かします。

[x-io Fusion](https://github.com/xioTechnologies/Fusion)の磁気センサーなしのAHRSを使用します。
同梱コミットは`a8d7224f36a0ec82345ef49a3db50e65f8d3bab8`です。
上流の必要なCソース・ヘッダーを変更せずに同梱し、取得元とMITライセンスを添付しています。
M5Unifiedの保存オフセットと自動校正を無効化し、このアプリで計測したジャイロバイアスを使用します。

BMI270を100Hz、加速度±8g、ジャイロ±2000dpsで設定します。
専用のセンサータスクで実測サンプル間隔をAHRSへ渡し、UDP送信は別タスクで最大50Hzにします。
USBも専用タスクで最大50Hzで送信し、送信バッファに空きがなければその回の姿勢を飛ばします。
画面描画、Wi-Fi再接続、USB設定でセンサータスクを待たせません。
250ms以上新しいデータを取得できなければIMUエラーを送り、復帰時は姿勢推定を初期化します。

## OSC仕様 v1

IPv4ユニキャストのUDPを使用します。FWから送るのはOSCメッセージ1個、80バイトです。
バンドルは使いません。文字列はOSCの4バイト境界に合わせてゼロで埋めます。
数値はネットワークバイト順です。

**FW → PC**

アドレスは`/headtracker/pose`、型タグは`,siiiffff`です。

| 順番 | 引数 | 型・意味 |
| --- | --- | --- |
| 1 | session | 16桁の小文字16進文字列。起動・再校正・IMU復帰時に更新 |
| 2 | sequence | 非負int32。送信ごとに増加し、2³¹で折り返す |
| 3 | state | int32。0=校正中、1=追跡中、2=IMUエラー |
| 4 | recenter | 非負int32。Aボタンごとに増加し、2³¹で折り返す |
| 5～8 | qw qx qy qz | 正規化クォータニオン、float32 |

校正中やIMUエラー時にも状態を送信しますが、PCはその姿勢をSceneRotatorへ転送しません。
正面設定カウンターを後続パケットにも載せるため、操作時のパケットが失われても次の受信で検出できます。
PCは重複・順序逆転、既に終了したセッション、長さ・型・値が不正なパケットを除外します。
1台だけを対象とし、最初の有効な送信元IPに固定します。
別の本体や疑似送信へ切り替えるときは「接続開始 / 再開」を押してください。

**PC → SceneRotator**

初期値は`127.0.0.1:9001`、アドレスは`/SceneRotator/quaternions`、型タグは`,ffff`です。
引数は`qw qx qy qz`の順です。[IEM公式OSC仕様](https://plugins.iem.at/docs/osc/)

正面姿勢を`q₀`、現在姿勢を`q`とし、表示には`q₀⁻¹ × q`を使用します。
SceneRotatorにはその逆回転を送ります。正規化済みのクォータニオンなので共役で逆回転を求めます。
描画は約30Hz、中継は受信時に実行します。受信が滞って複数パケットが届いた場合は最新姿勢だけを送ります。
500ms以上有効な姿勢が届かなければ中継を止めます。復帰時は最新データから再開します。

GUIの「送信中」はUDP送信成功を示します。SceneRotatorでの受信や音声の動作を保証する表示ではありません。
最終受信からの時間はPCの受信時刻を基準とし、無線の片道遅延ではありません。

## USB仕様

115200bps、UTF-8のJSON Linesです。PCが発行した`id`を応答にも返します。
Wi-Fi入力での本体設定は、接続直後に`status`でFWの応答を確認してから送ります。
USB入力では`stream`の応答を確認し、姿勢の受信と設定・状態取得を同じワーカーで処理します。
起動メッセージなどJSON以外の行は読み飛ばします。

```json
{"cmd":"status","id":"example1"}
{"cmd":"configure","id":"example2","ssid":"YOUR_SSID","password":"YOUR_PASSWORD","receiver_ip":"192.168.1.10","receiver_port":9000}
{"cmd":"receiver","id":"example3","receiver_ip":"192.168.1.10","receiver_port":9000}
{"cmd":"stream","id":"example4","enabled":true}
{"cmd":"stream","id":"example5","enabled":false}
```

応答には`ok`、失敗時の`error`、SSID、受信先、Wi-Fi状態、本体IP、追跡状態、`usb_stream`を含めます。
診断用に`uptime_ms`、`sample_count`、`quaternion`、変換後の`accel`（g）と`gyro`（degree/second）も返します。
本体の方向表示の診断として`front_reference_valid`と、現在の頭部座標で表した基準正面の単位ベクトル
`front_direction`（前・左・上の順）も返します。後者は追跡中で基準が有効な場合だけ含めます。
`sample_count`は姿勢推定の再初期化でゼロに戻ります。
パスワードは返しません。SSIDは1～32バイト、パスワードは0～63バイト、ポートは1～65535です。
`receiver`は保存済みのSSID・パスワードを変更せずに送信先だけを更新します。
最大1024バイトを超える入力行は破棄します。設定はNVSへの保存成功後に有効化します。

### USB姿勢ストリーム

`stream`の`enabled:true`で約50HzのJSON Lines送信を開始します。USB入力を選んだPCアプリが自動で開始します。

```json
{"type":"pose","session":"0123456789abcdef","sequence":123,"state":1,"recenter":0,"quaternion":[1,0,0,0]}
```

`session`、`state`、`recenter`、クォータニオンの順序・座標系はOSCと共通です。
`sequence`はUSB専用の非負31bit連番で、セッションが変わると0に戻ります。
Wi-FiとUSBの連番はそれぞれ独立しています。PCでは同じ姿勢検証・正面設定・逆回転処理へ渡します。
設定応答は`id`、姿勢は`type:pose`で区別します。分割された行や複数行をまとめた受信にも対応します。

PCアプリは2秒ごとに`enabled:true`を送り、連続送信を維持します。
5秒以上更新がなければFWは送信を停止します。通常の入力切り替え・終了時には`enabled:false`を送ります。
送信のON/OFFはNVSに保存しません。USBを外してもセンサー取得とWi-Fi送信は継続します。
USB接続のDTRはON、RTSはOFFで開きます。他のシリアルモニターとは同時利用できません。

## SceneRotatorへの接続

SceneRotatorと使用するバイノーラルデコーダーは、[IEMの公式ダウンロード](https://plugins.iem.at/download/)から事前にインストールしてください。

1. DAWでAmbisonics音源を用意し、SceneRotator → バイノーラルデコーダーの順で挿します。ステレオ音源なら前段でAmbisonicsへエンコードします。
2. SceneRotatorと前後のプラグインでAmbisonicsの次数・正規化・チャンネル数を合わせます。
3. SceneRotator左下のOSC設定を開き、受信ポート9001を指定してOPENします。
4. SceneRotatorのQuaternionとYaw/Pitch/Rollの反転設定をすべてOFFにします。逆回転はPCアプリで計算します。
5. PCアプリの送信先を`127.0.0.1:9001`にして「中継ON」を選びます。
6. 正面を設定し、左へ向いたときにSceneRotatorが逆方向へ回転することを確認します。上下・首の傾きも個別に試します。
7. 複合回転でも音源が部屋に固定されて聞こえるか確認します。

受信ポート9000はPCアプリ専用、9001はSceneRotator専用です。同じポートを両方で開かないでください。
SceneRotatorからPCアプリへのOSC送信は不要です。
詳細は[SceneRotator Guide](https://plugins.iem.at/docs/scenerotator/)と[IEM OSC Control](https://plugins.iem.at/docs/osc/)を参照してください。

## テスト

実機なしでPCアプリを試す場合は、GUIの入力をWi-Fiにして、別ターミナルから疑似姿勢を送れます。
記録済みデータの再生機能ではなく、テスト用の角度をその場で生成します。

```powershell
uv run --project tools/head-tracker-monitor --frozen head-tracker-simulate
```

自動テストは次のコマンドで実行します。

```powershell
uv run --project tools/head-tracker-monitor --frozen python -m unittest discover -s tools/head-tracker-monitor/tests -v
```

Quaternionの単独・複合回転、正面設定、逆回転、OSC型と並び、不正パケット、連番の折り返し、
通信停止と復帰、実際のループバックUDP中継、USB応答の機密情報除外、GUI描画を確認します。
USBの行分割・結合・不正データ、継続受信中の設定、切断と再接続、入力切り替え後の古い姿勢の除外も確認します。
GCCと同じ場所のG++があればFWのC/C++コードもホストで実行し、静止校正と90度の回転、
FWとPythonのOSCバイト列の一致を確認します。下向きと左耳上げを30度まで動かして3秒保持する
センサー入力も与え、PitchとRollが入れ替わらず角度を維持することを確認します。
コンパイラーがなければこの1件だけスキップします。

描画確認用の画像は`.cache/head-tracker-tests/monitor.png`に生成します。
テストのGUI設定は同じディレクトリに保存し、普段のユーザー設定には触れません。

SceneRotatorを起動せずに中継出力を10分間測定する場合は、次を実行してGUIの中継をONにします。
実際のSceneRotatorが9001を使用している間は、この受信ツールを同時に起動できません。

```powershell
uv run --project tools/head-tracker-monitor --frozen python tools/head-tracker-monitor/tests/soak_scene.py --seconds 600 --report .cache/head-tracker-tests/hardware-soak.json
```

受信頻度、最大受信間隔、500ms以上の途切れ、不正パケット、最初と最後の角度を記録します。
途中で本体を動かした場合、角度の変化をドリフトとして扱うことはできません。

### 実機チェック

- 起動後に静止させ、校正中から追跡中へ変わる。
- USBで設定を保存し、本体を再起動しても設定が残る。
- USBを外し、電池でOSCを送れる。
- USB入力で姿勢を連続受信し、Wi-Fiとの切り替え後も表示と中継が動作する。
- USB切断後に中継が止まり、同じポートへ再接続すると再開する。
- 左を向くとYawが正、下を向くとPitchが正、左耳を上げるとRollが正になる。
- AボタンとGUIの正面設定で全軸がゼロに戻る。
- Bボタン長押しで校正に戻り、完了後に基準を取り直す。
- Wi-Fi切断時もセンサー取得を続け、復帰後に再送信する。
- 10分間、受信頻度、切断の有無、Yawのずれ、再設定の効果を記録する。
- SceneRotatorで3軸と複合回転の補正を確認する。

- 実機 → Wi-Fi → PCアプリ → SceneRotator形式OSCの経路で600秒の継続確認を実施。29,825件、平均49.70Hz、受信間隔の中央値20.0ms、最大84.6ms。不正パケットと500ms以上の途切れはいずれも0件。
- 測定途中でUSBを外して置き直しているため、10分間の最初と最後の角度差は静止ドリフトの評価には使用していない。
- その後の静止60秒ではYawが約−1.50度変化した。今回の個体・温度・校正状態での観測値であり、性能保証値ではない。この測定でも不正パケットと500ms以上の途切れは0件。
- 実機でYawの方向とAボタンの正面設定、Bボタン長押しの再校正を確認。
- 初期の軸割り当てでPitchとRollの入れ替わりを確認したため、頭部座標への変換を修正。修正版で下向きPitchプラス、左耳上げRollプラスと、静止時の角度保持を実機で確認。
- 3D描画の投影と奥行き判定を同じ右手系カメラへ統一し、初期視点を後方へ変更。後方視点でのYaw・Pitch・Rollの画面上の動きを自動テストで確認。修正版で、利用者による実機操作と数値・3Dモデルの動きが一致することも確認済み。
- 本体の画面をオフスクリーン描画へ変更し、正面方向の矢印を追加。基準方向、左右90度、正面再設定、上下方向の計算をホスト実行テストで確認。実機のUSB応答で正面基準と方向ベクトルが有効になることを確認。利用者の実機確認で、周期的なちらつきの解消と正面を指し続ける矢印の動作を確認済み。画面更新を追加した状態でも、10秒間の中継は平均49.69Hzで不正パケットと500ms以上の途切れは0件。
- USBの連続送信を専用タスクへ分離し、COM4へ修正版FWを書き込み。USBを直接8秒間受信して400姿勢、約49.99Hz、連番の欠落なしを確認。
- 実機 → USB → PCアプリ → SceneRotator形式OSCを30秒間測定。1,309件、平均43.63Hz、最大受信間隔42.1ms。不正データと500ms以上の途切れは0件。Windowsで複数姿勢がまとめて届くと最新のみを採用するため、FWの送信頻度より中継頻度が下がることを確認。
- 同じPCアプリ上でUSB → Wi-Fi → USBを切り替え、続く12秒間の中継をそれぞれ49.61Hz、43.23Hzで確認。いずれも不正データと500ms以上の途切れは0件。USB受信中の状態取得も、同じ接続を共有して成功。
- 継続要求の更新を止めると、実機のUSB送信が約4.98秒で停止することを確認。状態応答でも`usb_stream:false`となり、その間のIMU取得は約98.1Hzで継続。
- USBケーブルの物理的な抜き差しによる再接続は未検証。疑似シリアルを用いた自動テストでは、切断・再接続と設定コマンドの共有を確認済み。
- 実際のWi-Fi切断・再接続、SceneRotatorでの音声補正は追加確認が必要。

## 接続できない場合

- USB応答がなければ正しいポートとFWを確認し、他のシリアルモニターを終了します。
- USBで姿勢を受信するには、今回の連続送信に対応した`head-tracker` FWを書き込んでください。
- USBをつなぎ直してポート名が変わった場合は、一覧を更新して選び直し、「接続開始 / 再開」を押します。
- SSID・パスワードが正しく、2.4GHzのネットワークか確認します。
- PC側の候補にはVPNなどのアドレスも出るため、本体と同じLANのIPv4を選びます。
- Windowsファイアウォールで利用中のPythonの受信を許可し、UDP 9000へ到達できることを確認します。
- ゲストWi-FiやAPの端末間通信禁止設定では同じSSIDでも通信できない場合があります。
- ポート使用中なら他の確認アプリを閉じるか、受信ポートを変えて本体にも保存します。
- IMUエラーやセッション変更が繰り返される場合は、本体を再起動してUSBの診断情報を確認します。
